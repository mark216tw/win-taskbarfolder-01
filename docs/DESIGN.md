# 系統設計文件（SDD）

本文件描述 TaskbarFolders 的需求、使用案例、資料流、介面設計、設計決策與驗收條件。技術實作細節請參閱[系統架構與技術文件](ARCHITECTURE.md)。

## 1. 目的與範圍

### 1.1 目的

在 Windows 11 工作列上提供「應用程式分類資料夾」體驗，讓使用者把大量圖示分組，點擊分類後快速啟動常用程式。

### 1.2 範圍

包含：

- 分類與應用程式項目的建立、編輯、排序、刪除。
- 開始功能表與 Microsoft Store / UWP 應用程式探索。
- 分類釘選捷徑產生與工作列飛出面板。
- 淺色／深色／跟隨系統主題與分類主題。
- 設定、圖示快取、記錄與視窗狀態保存。

不包含：

- 自動釘選工作列（Windows 限制）。
- 巢狀分類、全域熱鍵、系統匣常駐、開機自動啟動、自動更新。
- 雲端同步、跨裝置設定。
- 安裝程式或程式碼簽章。

### 1.3 目標使用者

- 工作列圖示過多、需要分組的 Windows 11 使用者。
- 需要快速切換多組工作情境（開發、文書、影音、遊戲）的使用者。
- 偏好可攜、免安裝、不要求系統管理員權限工具的使用者。

## 2. 名詞定義

| 名詞 | 說明 |
| --- | --- |
| 分類（Group） | 一組應用程式項目，對應一個工作列圖示與一個 AUMID |
| 項目（Item） | 分類內的單一應用程式、檔案、捷徑或網址 |
| AUMID | AppUserModelID，Windows 用來識別應用程式與工作列按鈕 |
| 飛出面板（Flyout） | 點擊分類圖示後在工作列上方展開的視窗 |
| 釘選捷徑 | 產生在 `%AppData%\TaskbarFolders\Shortcuts` 的 `.lnk` |

## 3. 使用案例

### UC-01 建立分類

- 前置條件：程式已啟動，處於編輯器模式。
- 主要流程：
  1. 使用者按「新增分類」。
  2. 系統建立預設分類並套用「資料夾」圖示。
  3. 使用者修改名稱、圖示與主題。
  4. 使用者按「儲存」。
- 例外：名稱為空時保留預設名稱；儲存失敗顯示錯誤並保留未儲存狀態。

### UC-02 從開始功能表加入應用程式

- 前置條件：已選取分類。
- 主要流程：
  1. 使用者按「從開始功能表匯入」。
  2. 系統掃描開始功能表與 Store 應用程式（最多快取 60 秒）。
  3. 使用者搜尋並多選應用程式。
  4. 系統加入項目並顯示數量提示。
- 例外：掃描失敗顯示錯誤；部分項目無法解析時跳過並記錄。

### UC-03 加入檔案或網址

- 主要流程：
  1. 使用者按「加入檔案」或「加入網址」。
  2. 系統驗證輸入並加入目前分類。
- 例外：無效網址、無法讀取的檔案顯示錯誤。

### UC-04 拖曳排序分類

- 主要流程：
  1. 使用者在左側清單按住分類拖曳。
  2. 系統顯示浮動縮影與插入位置指示線。
  3. 放開後更新順序並播放動畫。
- 例外：拖曳到無效位置時維持原順序。

### UC-05 儲存分類與更新捷徑

- 主要流程：
  1. 使用者按「儲存」。
  2. 系統寫入分類與 `.bak`，顯示模式沿用上次設定頁儲存的值。
  3. 系統只重建有變更的分類捷徑與圖示。
  4. 系統清理已刪除分類的殘留檔。
  5. 顯示成功橫幅。
- 例外：寫入失敗顯示錯誤；單一捷徑失敗不影響其他分類。

### UC-06 產生釘選捷徑並手動釘選

- 主要流程：
  1. 使用者按「產生釘選捷徑」。
  2. 系統建立所有分類捷徑並開啟釘選精靈。
  3. 使用者按「開啟資料夾」。
  4. 使用者在檔案總管右鍵 →「顯示更多選項」→「釘選到工作列」。
- 例外：Windows 更新後釘選失效，需重新執行。

### UC-07 使用飛出面板啟動應用程式

- 前置條件：分類已釘選到工作列。
- 主要流程：
  1. 使用者點擊工作列分類圖示。
  2. 系統以 `--group <id>` 啟動並載入設定。
  3. 系統在工作列上方顯示面板並背景載入圖示。
  4. 使用者以滑鼠或鍵盤選取項目。
  5. 系統啟動應用程式並關閉面板。
- 例外：分類不存在顯示錯誤；啟動失敗顯示錯誤訊息。

### UC-08 切換顯示模式

- 主要流程：
  1. 使用者按右上角「⋯」開啟設定。
  2. 選擇跟隨系統／淺色／深色。
  3. 按「儲存」寫入顯示模式；設定頁只儲存顯示模式，不寫入分類或捷徑。
- 例外：未按「儲存」就關閉設定時，還原上次儲存的顯示模式。

### UC-09 還原視窗狀態

- 主要流程：
  1. 編輯器啟動時讀取 `window.json`。
  2. 系統驗證尺寸與位置，必要時夾回可用虛擬螢幕範圍。
  3. 還原最大化狀態。
- 例外：檔案缺損或無效時使用預設大小。

### UC-10 匯出與匯入分類設定

- 匯出主要流程：
  1. 使用者在設定視窗按「匯出分類設定」。
  2. 選擇儲存位置，系統寫出包含所有分類的 JSON。
  3. 顯示匯出結果與檔案路徑。
- 匯入主要流程：
  1. 使用者按「匯入分類設定」並選擇 JSON。
  2. 系統驗證格式；確認後覆蓋目前所有分類。
  3. 立即寫入設定並同步捷徑，重新載入圖示。
- 例外：檔案格式錯誤或沒有分類時顯示錯誤，且不異動現有資料。

## 5. 非功能需求

| 類別 | 需求 |
| --- | --- |
| 相容性 | Windows 11 22H2 以上；x64 與 ARM64 |
| 效能 | 飛出面板冷啟動盡量縮短；視窗先顯示再補圖示 |
| 可靠性 | 設定寫入原子化；損毀可回退；單一捷徑失敗不影響其他分類 |
| 易用性 | 主要操作不超過三個步驟；破壞性操作需確認 |

| 可攜性 | 非 Self-Contained zip，解壓即可執行（需 .NET 10 Desktop Runtime） |
| 資源 | 圖示快取與記錄檔有上限與清理機制 |

## 6. 系統情境

```
┌─────────────────────┐
│   Windows 11 Shell  │
│  開始功能表 / Store │
│  工作列 / 檔案總管  │
└──────────┬──────────┘
           │ COM / Win32
┌──────────▼──────────┐        ┌────────────────────┐
│   TaskbarFolders    │◄──────►│ %AppData%          │
│  ┌───────────────┐  │        │  config.json       │
│  │ EditorWindow  │  │        │  config.json.bak   │
│  │ FlyoutWindow  │  │        │  window.json       │
│  │ SettingsWindow│  │        │  Shortcuts/*.lnk   │
│  └───────────────┘  │        └────────────────────┘
│  Services / Helpers │        ┌────────────────────┐
└─────────────────────┘◄──────►│ %LocalAppData%     │
                                │  IconCache/        │
                                │  Logs/             │
                                └────────────────────┘
```

外部互動：

- 檔案系統：讀取開始功能表、使用者加入的檔案；寫入設定、捷徑、快取與記錄。
- Windows Shell：COM（`IShellLinkW`、`IPropertyStore`、`IShellItemImageFactory`、`IApplicationActivationManager`）。
- 工作列：`Shell_TrayWnd` / `Shell_SecondaryTrayWnd` 位置查詢。
- 登錄檔：讀取 `AppsUseLightTheme` 判斷系統深色模式（唯讀）。

## 7. 主要資料流

### 7.1 建立與儲存分類

```
使用者輸入
  → EditorViewModel（驗證、預設圖示、未儲存狀態）
  → ConfigService.SaveAsync（.bak → .tmp → config.json）
  → ShortcutService.SyncAllAsync（STA）
      → 比對簽章
      → 重建需要的 .lnk / .ico
      → 清理殘留檔
  → 狀態橫幅
```

### 7.2 匯入應用程式

```
AppPickerWindow
  → DiscoveryService.DiscoverAsync
      → STA：掃描開始功能表
      → STA：列舉 shell:AppsFolder
      → 合併、去重、排序、快取 60 秒
  → EditorViewModel 加入項目
```

### 7.3 飛出面板啟動

```
捷徑（AUMID + --group <id>）
  → App.OnStartup
  → FlyoutLauncher.ShowAsync
      → ConfigService.LoadAsync
      → ThemeService.Apply / ApplyGroupTheme
      → FlyoutWindow.Show
      → IconService 背景載入
  → 使用者選取
  → LaunchService（Process.Start 或 ActivateApplication）
```

## 8. 介面設計

### 8.1 編輯器視窗

- 左側：分類清單、拖曳排序、新增分類。
- 中間：分類圖示按鈕（與名稱輸入框垂直置中）、名稱、主題、刪除。
- 圖示選擇面板依 6 個主題分區，主題標題與 10 個圖示顯示在同一列，必要時可垂直捲動。
- 右側：項目清單與加入／移除／改名／上下移動。
- 底部：狀態列與儲存、產生釘選捷徑、設定按鈕。
- 關閉時若有未儲存變更會提示。
- 沒有變更時儲存按鈕停用。

### 8.2 飛出面板

- 寬度 500 DIP，一列 5 個圖示。
- 標題列包含分類名稱與關閉按鈕。
- 高度依工作列外可用空間計算，最少 150 DIP。
- 不顯示垂直捲軸。
- 鍵盤：方向鍵、Enter、Esc。
- 滑鼠：點擊啟動、點擊外部關閉、項目右鍵「編輯顯示名稱」。
- 編輯顯示名稱會立即寫入設定，不影響原始檔案或捷徑。

### 8.3 設定視窗

- 顯示模式：跟隨系統／淺色／深色。
- 分類設定：匯出分類 JSON、匯入並覆蓋目前所有分類。
- 關於：顯示版本、檔案版本、授權、著作權與隱私說明，版本由組件屬性讀取。
- 儲存與關閉；儲存只寫入顯示模式，不寫入分類或捷徑。
- 沒有變更顯示模式時儲存按鈕停用。
- 儲存按鈕背景使用目前分類主題色；分類主題為「無」時使用全域強調色。
- 未儲存就關閉時還原上次儲存的顯示模式。

### 8.4 對話框

- 開始功能表應用程式挑選器（搜尋、多選、全選、清除選取）。
- 輸入對話框（網址、重新命名、編輯顯示名稱）。
- 釘選精靈（步驟說明與開啟資料夾）。
- 確認與錯誤訊息。

## 9. 狀態與錯誤處理

| 情境 | 行為 |
| --- | --- |
| 設定檔損毀 | 讀取 `.bak`；仍失敗則使用預設值 |
| 儲存失敗 | 顯示錯誤訊息，保留未儲存狀態 |
| 單一捷徑建立失敗 | 記錄錯誤，其他分類繼續 |
| 圖示取得失敗 | 顯示空白或字母備援圖示 |
| 分類不存在 | 顯示錯誤訊息並結束飛出面板 |
| 啟動應用程式失敗 | 顯示錯誤訊息，面板保持開啟 |
| 顯示名稱儲存失敗 | 顯示錯誤訊息，面板保持開啟並保留原名稱 |
| 匯入分類格式錯誤 | 顯示錯誤訊息，保留目前分類與設定 |
| 未處理例外 | 寫入記錄檔、顯示訊息、關閉程式 |
| 記錄檔過大 | 輪替為 `.log.1` |
| 圖示快取過舊 | 超過 30 天自動刪除（每日最多一次） |

## 10. 設計決策與取捨

### D-01 以 AUMID + 捷徑取代自動釘選

- 決策：每個分類產生帶獨立 AUMID 的 `.lnk`，由使用者手動釘選。
- 理由：Windows 11 不提供可靠的自動釘選 API；使用未公開 API 容易因更新失效。
- 取捨：首次設定需手動一步；換來穩定性與零系統修改。

### D-02 飛出面板為獨立程序

- 決策：每次點擊以 `--group` 啟動新程序。
- 理由：不需常駐程序，記憶體只在需要時使用；程序結束即釋放資源。
- 取捨：冷啟動比常駐方案慢；以精簡啟動路徑與 ReadyToRun 緩解。

### D-03 編輯器使用 DI、飛出面板手動建構

- 決策：編輯器使用 `ServiceProvider`；飛出面板只建立必要服務。
- 理由：降低飛出面板啟動成本。
- 取捨：兩條啟動路徑需分別維護。

### D-04 內建圖示而非自訂圖示

- 決策：只提供 60 個內建向量圖示（6 個主題，每主題 10 個），不再支援自訂圖示檔。
- 理由：自訂圖示增加格式轉換、縮放與失敗處理複雜度。
- 取捨：彈性較低，但介面一致且儲存更可靠。

### D-05 分類主題以視窗資源覆寫

- 決策：套用分類主題時只寫入該飛出視窗的 `Resources`。
- 理由：不影響全域主題與其他視窗。
- 取捨：每個主題需維護淺色與深色兩套色盤。

### D-06 非 Self-Contained 發佈

- 決策：Release 提供 x64 與 arm64 的非 Self-Contained zip。
- 理由：檔案較小、可共用系統執行階段。
- 取捨：使用者需先安裝 .NET 10 Desktop Runtime。

## 11. 風險與限制

| 風險 | 影響 | 緩解方式 |
| --- | --- | --- |
| Windows 更新使釘選失效 | 分類圖示消失 | 文件說明重新釘選流程 |
| 未簽章執行檔 | SmartScreen 警告 | 文件說明；未來可考慮簽章 |
| 高 DPI / 多螢幕差異 | 面板位置偏移 | 以實際像素與 WPF DPI 換算；持續實機驗證 |
| Shell COM 行為變動 | 匯入或捷徑失敗 | 例外隔離、記錄與降級 |
| 使用者刪除快取或設定 | 圖示空白或設定遺失 | 自動重建、`.bak` 回退 |
| 大量項目 | 面板需捲動 | 限制不使用捲軸，仍可用滾輪與鍵盤 |

## 12. 驗收條件

- 可建立至少 5 個分類，各自擁有不同圖示與主題。
- 可從開始功能表匯入傳統與 UWP 應用程式。
- 儲存後 `config.json`、`.bak` 與捷徑檔正確產生。
- 刪除分類後殘留 `.lnk` / `.ico` / `.sig` 會被清除。
- 產生的捷徑含正確 AUMID，釘選後可開啟對應飛出面板。
- 飛出面板在單螢幕 100% DPI 下正確貼齊工作列上緣。
- 方向鍵、Enter、Esc 與滑鼠操作皆正常。
- 淺色、深色與跟隨系統可正確切換並保存。
- 關閉編輯器後重新啟動可還原視窗大小與位置。
- 重複啟動編輯器只會有一個視窗。
- 分類設定可匯出為 JSON；匯入後分類、設定檔與捷徑一致更新。
- 單元測試全數通過，`dotnet format --verify-no-changes` 無差異。
- x64 與 arm64 非 Self-Contained zip 可解壓並在安裝 .NET 10 Desktop Runtime 後執行。
